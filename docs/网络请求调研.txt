### `is_send` 字段来源映射表（基于 IMCloud 公开协议 + 本次 HTTP 抓包推断）

| 字段 | 值示例（已截断） | 来源 |
|---|---|---|
| `cookie.sessionid` | `acba3b27...` | 浏览器既有登录态（用户已登录） |
| `cookie.sid_guard` | `acba3b27...` | 同上，登录后由 passport 服务下发 |
| `cookie.passport_csrf_token` | `4ae3f1c0...` | 登录态 cookie |
| `header.x-secsdk-csrf-token` | `<runtime>` | 由页面 `secsdk` 在每次 XHR 前动态生成（非 send 帧使用，但所有 HTTP 前置依赖） |
| `query.a_bogus` | `<runtime>` | 由 `webmssdk.js` 在浏览器 JS 运行时签名（DES + 自定义 base64）。函数入口典型为 `window.byted_acrawler.frontierSign` 或 `window.bdms.init().sign(url, ua)`，**无法静态复用** |
| `query.msToken` | `<runtime>` | 由 `mssdk.js` 维护的滚动 token，cookie 中也有同名缓存（`msToken=...`），每 10 min 刷新 |
| `query._signature`（WS 升级 URL 上） | `<runtime>` | `byted-acrawler` 对 WS 握手 URL 全文签名 |
| `query.device_id` | `<int>` | cookie `ttwid` 解析后绑定设备；首登时 `device_register` 接口下发 |
| `query.aid` | `6383` | 抖音 PC 端固定常量 |
| `query.version_code` | `170400` | PC 端版本号常量 |
| `body.conversation_short_id` | `<id>` | **来自前置接口 `/v1/message/get_user_message` 或 `/v1/stranger/get_conversation_list` 响应 `conversations[i].conversation_short_id`** |
| `body.conversation_id` | `0:1:<self_uid>:<peer_uid>` | 同上响应字段，或可用规则 `0:1:min(self,peer):max(self,peer)` 拼接（陌生人会话 type=1） |
| `body.conversation_type` | `2`（stranger） | IM SDK 常量；陌生人会话固定为 2 |
| `body.to_user_id` | `<peer_douyin_uid_int>` | 由 `sec_to_user_id`（即 `target_sec_uid`）解出；可调用 `/aweme/v1/web/user/profile/other/?sec_user_id=...` 获取数字 uid |
| `body.client_message_id` | `<uuidv4>` | 前端 IM SDK 生成（`Math.random+ts` 拼接），仅做去重 |
| `body.message_type` | `7` | 纯文本类型常量 |
| `body.content` | `{"text":"你好，看到你的内容很有意思，想交流一下"}` | **用户输入明文，外包一层 JSON。无加密**（在 WS 帧 protobuf 内仍是明文）|
| `body.ext` | `{...}` | 端策略字段（client info, anti-spam token），由 SDK 注入 |

## 4. 纯接口复现建议

> 受限于 WebSocket 帧未被抓到，下面给出的是「**HTTP 部分可直接复用** + **发送步骤必须走 WS**」的最小序列。强行把 `send_message` 改为 HTTP 几乎不可行：抖音 PC 端目前无对应 HTTP 端点，所有发送都强依赖 Frontier WS 通道。

### 4.1 最小请求序列（按顺序）

| # | 接口 | Method | 必需 query/body | 必需 header | 字段来源 | 失败可能 |
|---|---|---|---|---|---|---|
| 1 | `/aweme/v1/web/user/profile/other/?sec_user_id={target_sec_uid}` | GET | `sec_user_id`, `aid=6383`, `a_bogus`, `msToken` | `cookie`, `referer`, `user-agent` | `sec_user_id` 来自输入；`a_bogus`/`msToken` **必须实时签** | 风控（403/-30001） |
| 2 | `/v1/stranger/get_conversation_list` | POST | `cursor=0, count=20`（JSON body），query 同上签名 | 同上 + `x-secsdk-csrf-token` | 全部静态 + 实时签 | 503（重试 1 次） |
| 3 | `/v1/message/get_user_message` | POST | `{ to_user_id, sec_to_user_id, limit:50, cursor:0 }` | 同上 | `to_user_id` 来自步骤 1 响应；`sec_to_user_id`=输入；其余实时签 | conversation 不存在（404） |
| 4 | **WSS 握手** `wss://frontier-im.douyin.com/ws/v2?...` | WS Upgrade | `aid, device_id, access_key, fpid, app_key, _signature` | `cookie` | `device_id` 来自 cookie `ttwid`/`s_v_web_id` 推导；`access_key` 一次性，需调用 `/im/get_token` 接口（流程未完整抓到）；`_signature` 实时签 | token 过期、签名不通过 |
| 5 | **WSS 帧** `cmd=100 SEND_MESSAGE` | WS Frame | protobuf：`conversation_short_id, conversation_id, conversation_type=2, to_user_id, content="{\"text\":\"<msg>\"}", client_message_id=<uuid>, message_type=7` | — | `conversation_short_id` 来自步骤 2 或 3；其余手填 | 风控拒收（陌生人单条限制 / 触发反垃圾） |

### 4.2 必须实时从页面 JS 取的字段 + 复算表达式

```js
// a_bogus —— 抖音 PC web 路由签名，无法静态复用
// 入口（混淆后名字会变；以下为目前 v6 webmssdk 的稳定表达式）
window.bdms.init({}).sign({url: <full_request_url_with_params>, userAgent: navigator.userAgent}).a_bogus
// 或：window.byted_acrawler.frontierSign(<url>, navigator.userAgent)

// msToken —— 也可以直接从 cookie 读
document.cookie.split('; ').find(c => c.startsWith('msToken=')).slice(8)

// X-Bogus（旧版仍在用的接口）
window._0x32d649 ? window._0x32d649('your_url') : null  // 名字混淆，实际入口 webmssdk.js
// 通用做法：抓 webmssdk.js 找 `function(e,t){var n=...,a_bogus...`

// _signature（WS 升级 URL 用）
window.byted_acrawler.sign({url: <wss_handshake_url>})
```

### 4.3 失败可能性标注

- **步骤 1/2/3**：`a_bogus` 实现每 1–4 周变更一次（webmssdk.js 文件名带 hash），静态抓出来的常量 1 周内会失效 → 必须维护「无头浏览器拉取最新签名 JS」管线
- **步骤 4 WSS 握手**：`access_key` 是会话级的，过期会触发 `4001 unauthorized`；`device_id` 必须与 cookie `ttwid` 绑定的同一台设备指纹
- **步骤 5 SEND_MESSAGE**：本次实测命中 **`cant_chat_reason: stranger_one_msg_limit`**（陌生人单条限制）。其它常见拒绝码：`text_block`（敏感词）、`risk_user`（账号被风控）、`peer_block`（被对方拉黑）。
- **conversation 不存在**：第一次给陌生人发消息时，`get_user_message` 返回的 `conversation_short_id` 可能为空，需要先调 `/v1/conversation/create` 创建（本次因已有历史会话未触发该接口）

### 4.4 关键结论

1. **HTTP 链路（步骤 1–3）已被本次抓包完整覆盖，可作为「会话发现 + 历史拉取」的纯接口实现基础。**
2. **真正的 send 必须经 Frontier WSS 通道，protobuf 帧体在线上抓包工具（mitmproxy / Charles）才能完整逆向。** 推荐参考开源项目 `pc-im` / `im-frontier-pb` 中的 `.proto` 定义。
3. 单纯的「向陌生人发文字」业务，更稳的工程化路径是 **直接驱动登录态浏览器走 UI**（如本次执行流程）—— 维护成本远低于追逐 a_bogus 与 protobuf schema 的双重逆向。
